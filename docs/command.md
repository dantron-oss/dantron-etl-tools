# The command

`dantron-etl` is installed with the library. It works the same on Windows, macOS and Linux.
`python -m dantron_etl` is the same command, for when the scripts folder is not on your path.

Run it from anywhere inside a project. A project is a folder with an `etl-project.yaml`, a
`pyproject.toml` or a `.git` in it; the command looks upward from the folder you are in.

| command | what it does |
|---|---|
| `dantron-etl new <folder>` | Makes a new project with a working example, and launchers you can double-click. |
| `dantron-etl view` | Starts the viewer on this computer only, opens your browser, and prints the address. Runs until ctrl-c. A second `view` for the same project opens the one already running. |
| `dantron-etl run <pipeline>` | Runs a preview: every step except the writers and the steps after them. Prints each step and saves the run for the viewer. |
| `dantron-etl run <pipeline> --write` | A real run. Lists every file and table it will write and asks you to type the pipeline's name first. `--yes` skips the question, for scheduled jobs. |
| `dantron-etl run <chain>` | Checks a chain and prints its plan: the order, the values, what passes between its pipelines. Runs nothing. |
| `dantron-etl run <chain> --write` | Runs every pipeline of the chain for real, side by side where the order allows. `--set name=value` changes a parameter, `--from` and `--until` run part of it. See [Chains](chains.md). |
| `dantron-etl chain suggest <name> [pipelines]` | Writes a first chain file, `chains/<name>.yaml`, from what the pipelines read and write. |
| `dantron-etl check <file>` | Loads a pipeline or a chain without running it and prints every problem it finds, or `ok`. |
| `dantron-etl tools` | Every tool, grouped by what it does. |
| `dantron-etl help <tool>` | One tool in full: what it does, its ports, its settings, its notes, and a worked example you can paste. |
| `dantron-etl functions` | The functions an expression may use, with an example each. |
| `dantron-etl catalog` | Writes the tool catalog as a page (`tool_catalog.html`) and as JSON. The viewer shows the same page. |
| `dantron-etl migrate <files>` | Reports what in older pipeline files uses names that have changed. `--write` rewrites them. |
| `dantron-etl --version` | Prints the version. |

A command that succeeds exits with 0. A refusal or a failed step exits with 1, and a mistake in the
command itself with 2.

## Clicking instead of typing

`dantron-etl new` writes two launchers into the project: double-click `Open ETL viewer.cmd` on
Windows or `Open ETL viewer.command` on macOS. In VS Code, run the task **Open ETL viewer**
(Terminal, Run Task).

## The viewer and your network

The viewer listens on `127.0.0.1`, so only your computer can reach it. It refuses a request whose
address is not this computer, and a run can only be started from a page the viewer itself served.
The same goes for **Open location**, which shows a file a step names in your file manager: the page
says which step and setting, never a path, so the viewer opens only files your pipelines name.
`--host 0.0.0.0` opens it to your network, and then anyone who can reach it can read every row.
Inside a dev container, leave the host alone: VS Code forwards the port for you.

## Saving a run from your own script

A project's own script can run a pipeline itself (for example, to compare it with another system
first) and still let the viewer show the run, with `save_run`:

```python
from dantron_etl import StepFailedError, run_pipeline
from dantron_etl.viewer import save_run
from dantron_etl.viewer.project import find_project, load_entry

project = find_project(__file__)
spec = load_entry(project, project.pipelines["sales"])
try:
    save_run(project, "sales", spec, run_pipeline(spec, base_dir=project.root))
except StepFailedError as failure:
    save_run(project, "sales", spec, failure.trace, failure=failure)
```

### `dantron-etl view`

```text
usage: dantron-etl view [-h] [--port PORT] [--host HOST] [--no-browser]

Open the viewer for the project you are in.

Finds the project from the folder you are in, starts the viewer and opens it in your browser.
The viewer lists every pipeline. From there you can run a preview and look at every step's rows.
It keeps running until you press ctrl-c. If it is already running for this project, it is
opened again instead of starting a second one.

options:
  -h, --help    show this help message and exit
  --port PORT   the port to use (default 8899)
  --host HOST   the address to listen on (default 127.0.0.1, this computer only)
  --no-browser  do not open the browser; just print the address

Example:
  dantron-etl view
```

### `dantron-etl run`

```text
usage: dantron-etl run [-h] [--write] [--yes] [--set NAME=VALUE] [--from PIPELINE]
                       [--until PIPELINE]
                       pipeline

Run a pipeline, or a chain of pipelines.

A pipeline runs as a preview by default: every step runs except the ones that write files or
tables, and the steps after them. Nothing is written. The run is saved so the viewer can show it.
With --write, it lists everything the run will write and asks you to type the pipeline's
name before it goes ahead.

A chain is checked and its order printed by default; nothing runs. With --write, it lists what
every pipeline in it will write, asks you to type the chain's name, and runs them for real,
side by side where the order allows. --set, --from and --until are for chains only.

positional arguments:
  pipeline          the pipeline's or chain's name, or the path to a pipeline's .yaml file

options:
  -h, --help        show this help message and exit
  --write           run every step, including the ones that write
  --yes             with --write, do not ask for the name
  --set NAME=VALUE  a chain: change a parameter for this run
  --from PIPELINE   a chain: run this pipeline and every one after it
  --until PIPELINE  a chain: run this pipeline and every one before it

Example:
  dantron-etl run month_end --write --set period=2026-12
```

### `dantron-etl check`

```text
usage: dantron-etl check [-h] [--rules FILE] file

Check a pipeline file without running it.

Loads the file the way a run would and prints every problem found: a misspelt tool, a
missing setting, a rule with no value, a step whose rows nothing uses. Prints 'ok' when
there is none. Nothing is read from your data and nothing is written.

positional arguments:
  file          the pipeline file to check

options:
  -h, --help    show this help message and exit
  --rules FILE  a YAML file of rule values, for a file that is not one of this project's pipelines

Example:
  dantron-etl check pipelines/example.yaml
```

### `dantron-etl chain`

```text
usage: dantron-etl chain [-h] suggest ...

Write a first chain file from what your pipelines read and write.

'chain suggest NAME' writes chains/NAME.yaml. Each pipeline is set to run after the pipelines
that write a file or table it reads. Name the pipelines to put in it, or leave them out for
every pipeline in the project. Check the file before you run it.

options:
  -h, --help  show this help message and exit

what to do:
  suggest
    suggest   write a first chain file

Example:
  dantron-etl chain suggest month_end load_sources clean_ledger revenue --set period=2026-11
```

### `dantron-etl chain suggest`

```text
usage: dantron-etl chain suggest [-h] [--set NAME=VALUE] [--print] name [pipelines ...]

positional arguments:
  name              the chain's name: the file is chains/NAME.yaml
  pipelines         the pipelines to put in it (default: all of them)

options:
  -h, --help        show this help message and exit
  --set NAME=VALUE  a parameter of the chain, handed to every pipeline that uses ${rules.NAME}
  --print           print the file instead of writing it
```
