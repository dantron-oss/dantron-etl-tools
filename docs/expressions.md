# Expressions

An expression is a small formula, like a spreadsheet formula, written inside a step's settings. It
works out one value for each row. `filter` keeps the rows where it is true, `formula` writes it as a
new column, `case_when` picks between several, and `group_by` totals it.

```text
[amount] > 0 and [status] = 'OPEN'
coalesce([discount], 0.0)
concat('order ', [number])
days_between([starts_on], [ends_on], 'inclusive')
[placed_on] >= date'2025-01-01'
```

Only some settings are expressions. `dantron-etl help <tool>` shows each setting's type, and an
expression setting has the type `expression`. Everything else (a path, a pattern, a sheet name, a
column name) is plain text.

In the pipeline file, put the whole expression in double quotes and use single quotes inside it:
`predicate: "[status] = 'PAID'"`.

## What you can write

| you write | it means |
|---|---|
| `[amount]` | the value in column `amount`. Any column name works between brackets, spaces included: `[unit price]` |
| `'PAID'` | text. Single quotes only. Write a quote inside text twice: `'O''Brian'` |
| `42`, `-3`, `0.5` | numbers |
| `true`, `false`, `null` | true, false, and no value |
| `date'2025-01-31'` | a date |
| `+ - * /` | arithmetic |
| `= != < <= > >=` | comparisons |
| `and`, `or`, `not` | logic |
| `[code] in ('A', 'B')` | true when the value is one of a list |
| `[code] is null`, `[code] is not null` | whether a value is missing |
| `name(...)` | one of the functions below |

There is nothing else: no variables, no loops, no functions of your own. The expression is read and
checked by the library, never run as Python code, so a pipeline file is safe to accept from someone
who does not program.

A function argument "written in the file" must be typed into the expression itself, not taken from
a column: a number of decimal places, a separator, a pattern. Those are decisions a reader should
see in the pipeline, the same on every row.

## Rules worth knowing

**Missing values.** Almost every operation on a missing value (`null`) gives `null`. `[a] + [b]` is
null when either is. A comparison with null is null, and `filter` treats null as not true, so the
row goes to `false`. `[code] = null` is never true: write `[code] is null`. That mistake is refused
when the file loads.

**Rounding.** `round` rounds a half away from zero, as a spreadsheet does: `round(2.5, 0)` is `3`,
`round(-2.5, 0)` is `-3`. It works on the number as you would write it, so `round(1.005, 2)` is
`1.01`, even though the computer stores 1.005 as slightly less. `format_number` gives the same
digits as `round`.

**Dividing by zero stops the step.** A `/` whose divisor is zero on any row the step uses stops the
run and names the step, the setting and up to five rows. A divisor written as `0` is refused when
the file loads. A null divisor is not zero: the answer is null. To divide only where the divisor is
not zero, use `case_when` with a case for zero before the case that divides:

```yaml fragment
tool: case_when
config:
  output: share
  cases:
    - {when: "[total] = 0", then: "0.0"}
    - {when: "true", then: "[part] / [total]"}
```

`case_when` checks each case only on the rows that reach it. A guard inside one expression,
`[b] != 0 and [a] / [b] > 1`, does not help: every part of an expression is worked out on every row.

**Whole numbers written in an expression are small.** `0` or `1` in a `formula` makes a 32-bit
whole-number column. That is fine for a count or a rank. For a large value, `cast_columns` the
column to `Int64` first; arithmetic past the 32-bit range gives a wrong number.

**Dividing a `Decimal` column keeps its places.** `100.00 / 3` on a `Decimal` column with two places
is `33.33`. Cast it to `Float64` first if you need more.

**A timestamp compared with a date** reads the date as midnight at its start. So
`[posted_at] <= date'2025-01-31'` leaves out the 31st after midnight. `>=` and `<` are allowed and
mean what they say; `<=`, `>` and `=` against a date are refused. Cast the timestamp to `Date` first,
or write the range as `>= start and < next day`.

**Not-a-number is not null.** A source can hold not-a-number (NaN). It counts as larger than every
number, so `[ratio] > 0.5` is true for it, and `sort` puts it after every number.

**Types are checked when the step runs**, against the columns that really arrive. `upper([amount])`
on a number column loads, and is refused when that step starts, before it reads a row.

## Text

- `trim` removes spaces at the start and end. Unlike a spreadsheet's TRIM, it leaves spaces inside
  the text alone.
- `regex_replace`'s replacement is plain text: `$1` is the two characters `$1`, not the first
  group. To rearrange a match, pull the pieces out with `regex_extract` and join them with `concat`.
- `regex_extract([ref], '[0-9]+', 1)` asks for group 1 of a pattern that has no groups, and is
  refused. Write `'([0-9]+)'`, or ask for group 0, the whole match.
- `concat` gives null when any part is null. Use `coalesce([part], '')` for a part that may be
  missing.

## Numbers as text

`format_number(value, decimals, thousands_separator, decimal_separator)` writes a number as text.
`format_number([total], 2, ',', '.')` gives `651,623.80`, and `format_number([total], 3, '.', ',')`
gives `123.456,789`. All four arguments are required. A negative figure that rounds to zero keeps
its sign: `-0.00`. Not-a-number and infinity give null. It works a row at a time, so use it near
the end of a pipeline, on the rows people read.

## Stable ids

`uuid5(namespace, value)` makes the same 36-character id from the same text every time, on any
computer. It is useful when the natural key is several columns. Build the text with `concat` and a
separator, so `('ab', 'c')` and `('a', 'bc')` give different ids:

```text
uuid5('6ba7b810-9dad-11d1-80b4-00c04fd430c8', concat([code], '|', [period]))
```

The namespace is a UUID typed into the file. Make one per pipeline, once
(`python -c "import uuid; print(uuid.uuid4())"`), and never change it: changing it changes every
id. The value must be text. A null anywhere in it gives a null id; use `coalesce` on a part that may
be missing if you still want an id.

## Dates

`months_between(start, end, counting)` and `days_between(start, end, counting)` count whole months
or days between two dates. `counting` is `'inclusive'` (both ends count, so the same day is 1) or
`'elapsed'` (only completed months or days). They give exactly what the `date_diff` tool gives.

`make_date(year, month, day)` builds a date, and gives null for a date that does not exist, such as
30 February. `month_end(date)` is the last day of the date's month. `add_months` moves a date by a
whole number of months.

These take dates. A timestamp with a time zone is refused, because which day it falls on depends on
the zone. Cast it to `Date` with `cast_columns`, stating the zone with `in_zone`.
