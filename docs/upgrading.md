# Upgrading to 0.2

Version 0.2 renames some tools, settings and ports so their names say what they do, and changes
what a few operations do with awkward values. This page lists all of it. [CHANGELOG.md](../CHANGELOG.md)
has the rest of what is new.

## 1. Rewrite your pipeline files

An old pipeline file is refused when it loads, with a list of each old name and what it is called
now. The `migrate` command rewrites the files for you:

```bash
dantron-etl migrate pipelines/
dantron-etl migrate --write pipelines/
```

The first line only reports what would change, file by file. The second makes the changes. It edits
the text of the file, so comments, layout and `why` text stay as they were. Give it your rules files
too: an expression in a rules file is rewritten the same way.

Where the old behaviour has become a setting you must state, the migration writes in the value
that keeps what your pipeline did before (for example `allow_empty: true` on a file writer). Read
its report: one thing it cannot see from the file is listed there for you to check by hand.

Then run `dantron-etl check` on each file, and a preview of each pipeline.

A renamed value whose meaning changed with it:

- `n_unique` to `count_distinct`: count_distinct skips nulls, as SQL's COUNT(DISTINCT) does, where n_unique counted a null as one more value: a group holding a null counts one fewer.

A default that changed. The migration writes the old value into a step that relied on it:

- `date_diff`: `counting: inclusive`
- `connected_components`: `record_column: node`, `group_column: component`

- `publish_tables` in each `tables[]` entry where `mode: merge`: `when_incoming_is_null: keep_published`
- `write_csv`: `allow_empty: true`
- `write_excel` in each `sheets[]` entry: `allow_empty: true`

## 3. What now behaves differently

These change what a pipeline computes, or whether it runs. Check each against your own pipelines.

**`round` rounds a half away from zero, as a spreadsheet does.** `round(2.5, 0)` is `3` and
`round(-2.5, 0)` is `-3`. It reads the number as written, to 15 significant digits, so
`round(1.005, 2)` is `1.01`. Before, a half could round towards the even digit, and a value such as
1.005, which the computer holds as slightly less, rounded down. `format_number` gives the same
digits as `round`.

**Dividing by zero stops the step.** A `/` whose divisor is zero on any row the step uses stops the
run, naming the step, the setting and up to five rows. A divisor written as `0` is refused when the
file loads. Before, the answer was infinity or not-a-number, which counts as larger than every
number in a later `filter` or `sort`. A null divisor still gives null. Where zeros are expected,
guard with `case_when`: see [Expressions](expressions.md#rules-worth-knowing).

**`count_distinct` (was `n_unique`) skips blanks, as SQL's `COUNT(DISTINCT)` does.** `a, a, null, b`
counts 2, where `n_unique` counted 3. A group of nothing but blanks counts 0. To count a blank as a
value, count `coalesce([v], '(blank)')`.

**A decimal becomes a whole number only when it already is one.** `cast_columns` to `Int64` (and
`unpivot`'s `values_type`) reads `12.0` as 12, but stops on `1.99`, naming the column and the values.
Before, `1.99` became `1` without a word. Round it first: `round([seats], 0)`.

**A timestamp with a time zone needs the zone stated to become a date.** 23:30 on 31 January in
Toronto is 1 February in UTC, so the day depends on the zone. Casting such a timestamp to `Date`,
and `date_diff` and `expand_date_range` on one, now need `in_zone`. Write `in_zone: UTC` to keep the
dates you got before. The migration cannot see which columns carry a zone, so it lists this for you
to check.

**A `publish_tables` merge says what a blank incoming value does.** Each merge entry now needs
`when_incoming_is_null`: `keep_published` leaves the published value as it is, and `overwrite`
writes the blank, as SQL's `MERGE` does. There is no default. The migration writes
`keep_published`, which is what a merge did before.

**A spreadsheet tab refuses not-a-number and infinity.** `write_excel` used to write them as blank
cells, which read as "no figure". It now stops, naming the tab, the column and the rows. A null is
still an empty cell.

**File writers stop on an empty result unless the step allows it.** `write_csv` and `write_excel`
(per sheet) now refuse a frame with no rows until `allow_empty: true` says it may be empty, as
`write_table` and `publish_tables` already did. An empty file looks the same as a quiet month. The
migration writes `allow_empty: true` on every file writer that does not say, which keeps what it did
before.

**`first` keeps a blank first row.** This is unchanged, but now stated: `first` gives the first
row's value as it arrives, blank or not. The new `first_non_null` gives the first value that is
there.

## 4. Python code

Code that imports the library is not rewritten by the migration; it prints the names to change.
Everything needed to load and run a pipeline is now imported from the package itself:

```python
from dantron_etl import read_pipeline, run_pipeline
```

A tool author imports from `dantron_etl.authoring`. The old module paths (`dantron_etl.pipeline`,
`dantron_etl.tool`) are gone, with no stand-ins.
